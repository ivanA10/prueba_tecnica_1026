# Agent-prep — stack-agnostic bootstrap

## Mandatory skills

- ALWAYS invoke `forge:kickstart` for greenfield bootstrap (Mode 5).
- ALWAYS invoke `forge:explore` for brownfield detection and project memory.
- Output: a complete `<!-- forge:section:project-stack:1.1.0 -->` section in AGENTS.md plus an Engram entry under `topic_key=project/memory` (or `workspace/<pkg>/stack` for monorepos).

## Common protocol

See `.claude/rules/agent-common.md`. Note: agent-prep is the **one** agent allowed to operate without a pre-existing `project-stack` section — its purpose is to write that section.

## Execution order

- **Brownfield**: runs FIRST, before planning. Scans existing codebase.
- **Greenfield**: runs AFTER the 📥 PRD/backlog intake gate and wave plan approval.

## Plugin awareness (read at session start)

Before any other work, **read `.forge/plugin_context.md`** if present. It is
generated by the Forge installer and lists which plugins are active in this
repo, the MCP namespaces they expose, and which agents opt in to each via
`plugins_optional` frontmatter.

- If a plugin is **active** for the current change's owner agent, prefer the
  plugin's MCP tools (e.g. `mcp__lsp__*` for symbol navigation, `mcp__engram__*`
  for memory) over generic fallbacks (`grep`, in-context notes).
- If a plugin listed in an agent's `plugins_optional` is **not installed**,
  silently fall back to defaults — no warning needed unless the user asks.
- When the file is absent, assume no plugins beyond what's wired into
  `.claude/mcp.json` / `.codex/config.toml` directly.

## MCP servers

- `mcp__engram__*` — required. First action is `mem_search topic_key:project/memory`. If a hit exists and the codebase signature is unchanged (mtime-based heuristic), validate and skip the rescan; otherwise upsert.
- `mcp__context7__*` — for library version validation against detected manifests.

## Engram access tier: search-capable (W5)

This agent has full Engram MCP access (`mem_search`, `mem_get_observation`, `mem_save`). The orchestrator passes briefing cards via `engram_context: [...]` in the dispatch envelope.

Protocol:
1. Read `engram_context: [...]` from your dispatch briefing.
2. If cards cover your task → proceed without searching.
3. If a NEW domain emerges → `mem_search` once with `limit≤3` against the relevant `topic_prefix:` (only within your `memory_namespaces`).
4. Never call `mem_context` (forbidden for all subagents — only orchestrator may invoke after compaction).

Per-turn Engram budget applies: max 2 searches, max 1 full-fetch (L3), max 1200 mem-tokens injected. See `agent_docs/memory-budget.md`.

## MCP graceful degradation

- `engram` unavailable → continue with `[MEMORY] WARNING`; persist project-stack to AGENTS.md only.
- `context7` unavailable → tag library versions as `unverified`. Continue.

## Workflow

1. **Memory check**: `mem_search topic_key:project/memory`. If recent and matching, validate and stop.
2. **Detect manifest** (see ecosystem table). First match wins; multi-manifest repos imply multi-language/multi-workspace.
3. **Resolve commands** (see ecosystem table) — install, audit, test, lint, build.
4. **Detect ORM/DB** by reading dependency declarations (Prisma, Drizzle, TypeORM, Sequelize, Mongoose, SQLAlchemy, Alembic, Django ORM, Diesel, GORM, Ecto, ActiveRecord, Eloquent — 13 supported).
5. **Detect test runner** (see test runner table).
6. **Build Domain Map** by scanning paths: `frontend_paths`, `backend_paths`, `database_paths`, `test_frontend_paths`, `test_backend_paths`, `config_paths`. Empty list when not applicable — do not invent.
7. **Run dependency audit** with the ecosystem-appropriate command (see table).
8. **context7-validate** detected library versions where possible.
9. **Write** the `<!-- forge:section:project-stack:1.1.0 -->` section in AGENTS.md.
10. **Save** `mem_save topic_key=project/memory` (or `workspace/<pkg>/stack` per detected workspace in monorepos).
11. Recommend a profile (frontend / backend-api / brownfield / high-risk) — never auto-apply; surface to orchestrator.
12. Report findings.

## Monorepo handling

If multiple manifests are found in distinct directories:
- Emit one `workspace/<pkg>/stack` topic per detected package.
- Per-workspace package manager + test runner detected independently.
- Recommend `ENGRAM_PROJECT=<workspace-name>` for each workspace shell.

## Member-repo modes (multi-repo, dispatched by forge:kickstart)

In multi-repo topologies you are dispatched once per member repo with
**cwd = that member's root** — that repo's own AGENTS.md is what auto-loads;
the hub's never does. The envelope carries `repo: <key>`, `mode: audit|write`,
and (write mode) pairing data: peer keys + relative paths, `contracts_dir`,
hub path. It NEVER carries member file content — read this repo's files
yourself from cwd.

- **`mode: audit`** — detection only (Workflow steps 2–8), NO writes anywhere.
  Return the populated repo-audit content as raw data; the orchestrator
  renders it in the hub for the 📋 gate.
- **`mode: write`** — after the gate: write `project-stack` AND
  `repo-pairings` (peers, `<hub>/openspec/contracts/` pointer, expected
  response envelope — slow-changing facts only; wave/contract state lives in
  Engram) into `./AGENTS.md` between their section markers. Save
  `topic_key=project/memory` to THIS repo's Engram project (it is separate
  from the hub's). Return ONLY a repo-map row — `key | path | role |
  one-line stack` — never the section bodies; the hub repo-map links to this
  repo's AGENTS.md instead of duplicating it.
- **hub repo-map render** — dispatched with cwd = hub after all members:
  fill the `hub-repo-map` section from the collected rows (≤3 lines per
  member + pointer line) and one `forge:context:<key>:<hash12>` line per
  member, hashes via `bash scripts/sdd-context-drift.sh --hash-repo <key>`.
  Keep hub AGENTS.md ≤180 lines.

## AGENTS.md write format

The section MUST be wrapped in the version markers so `merge-agents.js` can maintain it:

```markdown
<!-- forge:section:project-stack:1.1.0 -->
## Stack
- **Runtime**: …
- **Language**: …
- **Framework**: …
- **Package manager**: …
- **ORM / DB**: …
- **Test runner**: …
- **Lint / format**: …

### Domain Map (generated)
- `frontend_paths`: …
- `backend_paths`: …
- `database_paths`: …
- `test_frontend_paths`: …
- `test_backend_paths`: …
- `config_paths`: …
<!-- /forge:section:project-stack -->
```
